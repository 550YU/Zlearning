# 新手解释质量检查清单

## 准确性

- [ ] 定义没有使用该概念本身进行循环解释。
- [ ] 已区分“是什么、有什么用、为什么有效、何时使用”。
- [ ] 包含、并列、流程、依赖和组合关系的方向准确。
- [ ] 数值、公式和性能结论注明了条件或近似性。
- [ ] 没有使用“彻底、一定、零损耗、任意、完全”等无条件绝对表述。
- [ ] 产品实现、行业通用原理和个人经验没有混为一谈。
- [ ] 正式标准、教学模型和产品实现已明确区分。
- [ ] 教学分层、记忆框架或观察视角没有被描述成新的正式标准。
- [ ] 简化示例已声明采用的协议、产品或场景范围。

## 新手友好度

- [ ] 前两段已经回答“它是什么”和“有什么用”。
- [ ] 已从来源重点、知识框架、机制和学习目标建立必要术语清单；没有以“新手友好”或“降低认知负荷”为由删除理解概念、配置、取舍或排障所需的术语。
- [ ] 首次出现的缩写和专业术语都有即时解释；“每次一个主要术语”通过排序实现，而不是通过删减术语实现。
- [ ] 核心术语只有在直觉/演示、定义、职责与关系、机制、边界、案例或练习形成闭环后才标记为 `covered`；只出现名称的项目仍标记为 `mentioned`。
- [ ] 已反向扫描每段依赖的术语；正文没有要求学习者使用尚未在前文完成教学的概念。
- [ ] 案例中的人物、设备编号、角色、数据对象、时间点和容量参数首次使用前均已解释，编号不承担概念说明。
- [ ] 一段只承载一个主要知识点。
- [ ] 原理被拆成3–5个连续步骤。
- [ ] 至少包含一个真实或生活化例子。
- [ ] 答案结尾有一句可复述的记忆总结。
- [ ] 主干正文没有混入大量不影响核心理解的标准历史、罕见例外或产品细节。

## 首次解释质量

- [ ] 首次主解释以场景或目标开场，并让学习者先看到问题、动作和结果。
- [ ] 正式术语出现在直觉台阶之后，随后只给最短必要机制和轻量关系收口。
- [ ] 首次解释没有以“X whereas Y”“X is not synonymous with Y”“X cannot prove Y”或抽象分类对立为主体。
- [ ] 章节标题、小标题和首句优先正向直述学习任务；否定式纠偏只在相关概念都已建立后使用。
- [ ] 严格分类、完整例外和诊断证据边界已移到进阶提示或后续辨析；立即必要边界仍保留一句。
- [ ] `whereas/but/cannot` 等词语扫描只用于候选定位，没有机械禁词。
- [ ] 删除术语后，仍能说出“谁遇到什么问题、系统做了什么、结果是什么”。

## 类比覆盖与质量

- [ ] 已建立核心概念类比覆盖台账；抽象、关系型、不可直接观察或容易混淆的首次核心概念与机制均有生活类比。
- [ ] 未采用类比的核心项已记录具体理由，并由实物、数值、报文或动作演示直接建立了准确心智画面；篇幅有限、已有定义或术语过多不算理由。
- [ ] 类比与专业机制在结构上相似，而不只是名称替换。
- [ ] 已逐项核对类比中的角色/对象、动作和结果与技术机制准确对应。
- [ ] 未把相邻概念或机制合并，例如 broadcast 与 unknown-unicast flooding。
- [ ] 专业概念与类比角色之间存在明确映射。
- [ ] 同一组概念尽量使用同一个故事背景。
- [ ] 已指出类比不能覆盖的技术边界。
- [ ] 多环节类比包含明确目标、判断、行动、交接和结果，而不是术语换名表。
- [ ] 故事先自然推进，再点出术语；映射表仅用于复盘，没有替代正文叙事。
- [ ] 课程章节在术语前已说明人物需求、当前阻碍、技术价值和实现效果。
- [ ] 章节入口故事与后续机制案例职责不同，没有重复叙述。

## 机制与原理质量

- [ ] 所有工作机制均已进入机制解释台账，而不只是首次概念进入台账。
- [ ] 每项机制都让学习者看见目标、当前信息、判断或动作、结果和下一交接。
- [ ] 图表标题、引导句、术语定义或组件列表没有替代连续机制解释。
- [ ] 删除术语后，仍能复述完整动作链，而不仅是说出输入和输出。
- [ ] 优先使用贯穿场景；抽象、关系型、不可直接观察或容易混淆的机制默认有生活类比，并准确映射对象、输入、动作、状态变化、结果和边界。
- [ ] 生活类比之后完整保留正式术语并重走真实技术链；没有用故事替代术语或机制。
- [ ] 技术映射紧跟故事或实例，没有停留在生活故事。
- [ ] 机制练习要求用自己的话重建过程或根据实例判断下一步。
- [ ] 没有为所有机制机械套用相同标题、段落数量或“Imagine/Think of/就像”句式。

## 学习结构

- [ ] 完整课程在详细目录和正文前有 4–7 行“学习主线速览”，且只预告课程走向，没有依赖未定义术语完成教学或冒充正式模型。
- [ ] 每个主干模块围绕一个清晰核心问题组织；章节入口由人物需求、阻碍、为什么需要和采用后结果自然展开，没有用“模块定位”等元话术替代场景。
- [ ] 每个主干模块的记忆锚点短、正向、可复述且准确，位于机制之后，没有替代定义、机制、关系或边界。
- [ ] 高频混淆概念优先集中为受控的 6–10 组核心关系速查，没有碎片化为大量辨析卡片。
- [ ] Word 保持连续阅读节奏；表格、图和卡片各自承担关系、对比、流程、布局或数值等独立学习任务，没有机械重复单格提示卡。
- [ ] 课堂演示建议只观察已教授机制中的动作或状态变化，并映射回正式机制，没有扩大课程范围或挤入学员主线。
- [ ] 先讲整体地图，再讲局部细节。
- [ ] 先讲问题，再讲方案和机制。
- [ ] 对易混概念给出了核心差异，而不是分别重复定义。
- [ ] 实际例子完整体现“现象—处理—结果”。
- [ ] 内容深度符合用户要求的“简洁、标准或课程”级别。
- [ ] 跨模块主题先给出了起点到结果的端到端主链路。
- [ ] 总览中的代表性概念与正文重点一致，没有只写宽泛类别。
- [ ] 跨层或分类存在差异的概念说明了教学位置、连接对象和作用边界。
- [ ] 端到端链路的每一步包含起点信息、判断、动作、结果和组件交接。
- [ ] 内容已分为主干知识、防误解边界和扩展细节。
- [ ] 排障测试使用证据四元组：观察、支持的判断、不能证明的范围、下一项区分性测试。
- [ ] 存在方向性的流程分别重建了正向和反向路径，没有用单向成功替代双向验证。
- [ ] 课程通过 Recognize、Explain、Reconstruct、Troubleshoot 四级能力验证学习结果。

## 存储专项门禁

- [ ] RAID 案例已明确物理成员、热备盘、保护组/镜像对、组合阵列和对外逻辑卷之间的关系。
- [ ] 已分别标注原始容量、单保护组可用容量、多个独立卷容量总和与组合阵列可用容量；未将六成员 RAID 1、三组独立双盘镜像和 RAID 10 混为同一种布局。
- [ ] 条带、chunk、校验、降级读写、重建和验证按依赖顺序解释，没有在 RAID 正式教学前用于完成主链说明。
- [ ] 分布式存储同时完整教授副本池和纠删码池，而不只是出现 replication/EC 名称。
- [ ] Ceph 内容覆盖 `size`、`min_size`、`k+m`、object→pool→PG→CRUSH→acting set→OSD、确认、peering、recovery/backfill 或 reconstruction、故障域与资源取舍。
- [ ] 已明确副本池和 EC 池提供集群内数据保护，但均不等于独立备份或历史恢复。

## 多材料覆盖

- [ ] 已提取每份来源中反复强调、单独成节、进入图表或案例的重点。
- [ ] 合并和去重没有误删名称相近但职责不同的概念。
- [ ] 每个来源重点都能在总览和对应正文中找到，必要时也进入案例或练习。
- [ ] 补充知识与来源内容区分清楚，没有伪装成原材料结论。
- [ ] 版本相关、产品相关或已过时的说法已注明适用条件或替代技术。
- [ ] 跨课程比较只迁移了故事连续性、机制链路、关系组织等教学能力，没有照搬另一主题的术语或章节。
- [ ] 教学能力迁移后已执行范围回归检查；新增地图、速查表、演示或章节结构没有引入来源范围外的新核心概念。

## 全课程一致性

- [ ] 核心结论在总览、学习目标、正文和案例中一致。
- [ ] 对比表与常见误区没有重新引入已修正的旧表述。
- [ ] 练习题和参考答案与正文采用相同的技术边界。
- [ ] 最终总结没有把条件化结论重新写成绝对结论。
- [ ] Word、PDF和PPT若同时交付，使用同一内容版本。
- [ ] 中文版和英文版是两个独立成品，而不是未经要求的逐段混排版本。
- [ ] 两个语言版本的知识结构、技术结论、适用边界、案例逻辑、练习范围和版本号一致。
- [ ] 英文版采用自然、专业的英文表达，没有因逐句直译产生含混或改变技术含义。

## 交付格式

- [ ] 完整课程默认分别提供中文版和英文版Word可编辑主版本。
- [ ] 正式生成前已询问是否需要PDF和PPT，或用户已经明确指定格式。
- [ ] 用户确认PDF或PPT后，默认按中文和英文分别生成，除非用户明确限制语言。
- [ ] PDF由定稿后的Word或PPT导出，没有独立维护另一份内容。

## 最终自测

如果以下三个问题均能从答案中直接得到回答，则结构基本合格：

1. 新手能否在30秒内说出这个概念是什么？
2. 新手能否画出或复述它的工作链路？
3. 新手能否分清它与最相近概念的差别？
4. 若有多份来源，能否逐项指出每个重点在成品中的位置？
5. 若使用故事，去掉术语标签后是否仍是一条完整、可跟随的事件链？

## 语义层隔离

- [ ] 已为核心解释记录 `explanation_mode`：`concept_first_analogy`、`analogy_first` 或 `direct_demonstration`，且选择理由符合对象的精确性与可观察性。
- [ ] 生活故事中没有数据库、对象、PV、VG、LV、PG、OSD 等技术主体。
- [ ] 生活故事中没有直接执行正式技术机制或调用产品组件。
- [ ] 技术数量与单位已转换为纯生活量，不把 `2 TB` 等技术值直接写入仓库故事。
- [ ] 生活事件先完整结束，映射在故事结束后独立出现。
- [ ] 映射明确区分“类比对象”和“正式技术对象”。
- [ ] 技术重放仅使用正式术语，没有残留 room、lease、warehouse、parcel 等隐喻词。
- [ ] 真实业务案例被明确标为应用场景，没有误计为生活类比。
- [ ] `concept_first_analogy` 先完成正式概念和最短机制，再给纯生活事件。
- [ ] 已人工复核 `pool/unit/member/page/chunk/stripe/object/shard/path/queue/target/lease/room/warehouse/parcel` 等词的当前语义层。
- [ ] 机制台账包含 `explanation_mode`、`semantic_layer_separation` 和 `hybrid_language_scan`，且状态为 pass。

## 整体写作自然度

- [ ] 没有把所有章节机械套入相同模板。
- [ ] 场景、概念、机制、类比、映射和边界按当前知识结构自然组合。
- [ ] 类比短于正式知识，没有喧宾夺主。
- [ ] 业务案例和生活类比的职责清楚：前者说明在哪里应用，后者解释为什么这样工作。
- [ ] 标题和首句正向直述学习任务，没有依靠否定式转折制造理解门槛。
- [ ] 术语、图示、案例、练习和答案形成覆盖闭环。
- [ ] 中英文版本保持相同解释模式和语义边界。
- [ ] MAPS 仅作为内部推演框架，没有形成机械八段式正文。
- [ ] 全文读起来像一门连续课程，而不是审计清单或术语索引。
