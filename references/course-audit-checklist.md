# Zlearning 课程内容审计清单

适用于完整教材、课程讲义、培训课件和多材料整合成品。审计用于内部回查，不必逐项展示给用户。

## 1. 标准与事实

- [ ] 正式标准注明了标准身份和适用范围。
- [ ] 教学模型、简化分层和记忆框架明确标为教学视角。
- [ ] 产品组件、默认行为和能力注明厂商、版本或配置条件。
- [ ] 通用概念没有被某一家产品的实现反向定义。
- [ ] “一定、保证、全部、始终、只能”等绝对表述均已检查成立条件。
- [ ] 简化示例说明了当前采用的协议栈、产品或场景。

## 1A. 来源与术语证据

- [ ] 产品事实可以追溯到产品、文档名、文档类型、版本、日期、语言和适用范围。
- [ ] 中英文术语优先采用同产品、同版本官方正文中的对应关系。
- [ ] 搜索摘要、营销页、旧版资料和内部材料没有覆盖更高优先级的当前官方定义。
- [ ] 中英文官方资料冲突已记录，且没有自行创造“官方统一译法”。
- [ ] 动态能力、命令、界面、授权、兼容性和性能结论绑定了目标版本与条件。
- [ ] 限定来源任务已建立来源清单、术语矩阵、覆盖矩阵和缺口表。
- [ ] 教学补充、类比、案例和练习明确属于教学设计，没有伪装成官方原文。

## 2. 认知负荷

- [ ] 已由来源重点、正式知识框架、工作机制和学习目标建立必要术语完整性清单。
- [ ] 主干知识足以支撑学习目标和端到端主链路；理解概念、配置、取舍或排障所需的术语、组件和机制没有因“新手友好”被删除。
- [ ] “每次只增加一个主要术语”通过前置依赖、排序和分步解释实现，而不是通过压缩术语范围实现。
- [ ] 必要例外以一句“注意边界”说明，没有打断主线。
- [ ] 标准历史、复杂变体、罕见例外和深层实现已移入扩展内容或省略。
- [ ] 首次出现的术语立即用日常语言解释。
- [ ] 覆盖矩阵区分 `mentioned` 与 `covered`；只有完成直觉/演示、定义、关系、机制、边界和应用闭环的核心术语才标记为 `covered`。
- [ ] 已反向检查正文术语依赖，未在正式教学前要求学习者理解后续概念。
- [ ] 案例人物、设备编号、磁盘角色、数据对象、时间、故障与替换关系在首次使用前已建立实体与参数台账。
- [ ] 每段只承担一个主要知识点。

## 2A. 首次解释与抽象对立句

- [ ] 已逐章建立核心概念首次解释台账，记录 chapter、concept、current issue、action（keep/rewrite/layer）和 reason。
- [ ] 首次主解释按“场景/目标 → 可观察动作 → 正式术语 → 最短机制 → 轻量收口”推进。
- [ ] `whereas`、`not synonymous`、`rather than`、`cannot/does not prove`、`do not confuse`、连续 `but/however` 等扫描结果仅作候选定位，并已人工判断上下文。
- [ ] 抽象对立句没有在缺少直觉台阶时承担首次主解释；严格分类、完整例外和证据边界已后移。
- [ ] 标题、小标题和首句优先正向直述任务或观察对象；否定式纠偏没有要求新手先理解尚未解释的错误选项。
- [ ] 立即必要且省略会形成错误模型的边界仍保留一句。
- [ ] 删除术语后，学习者仍能复述“谁遇到什么问题、系统做了什么、结果是什么”。
- [ ] 所有 rewrite/layer 台账项已在正文、图表、练习和答案中落实。

## 2B. 生活类比覆盖与准确性

- [ ] 已建立核心概念类比覆盖台账，记录 chapter/section、concept/mechanism、analogy_required、analogy_or_direct_demonstration、mapping、boundary、status 和 reason。
- [ ] 抽象、关系型、不可直接观察或容易混淆的首次核心概念与机制原则上均有生活类比；业务案例不能自动替代用于解释结构和因果的生活类比。
- [ ] `analogy_required=false` 的项目由实物、数值、报文或动作直接演示建立准确画面，并记录充分理由；篇幅限制、已有定义、术语太多或作者熟悉均不合格。
- [ ] 类比逐项映射了技术对象、输入、动作、判断、状态变化、结果和范围，且因果、方向一致。
- [ ] 相邻机制没有被类比合并成同一件事，例如 broadcast 与 unknown-unicast flooding、完整副本与纠删码数据/校验分片。
- [ ] 类比之后立即映射回完整正式术语和真实技术链，没有用生活故事替代必要术语或技术内容。
- [ ] 类比短于知识本身，优先复用贯穿场景，并在必要处注明边界。

## 2C. 机制与原理全覆盖

- [ ] 已建立独立机制解释台账，覆盖所有判断、转交、状态变化、请求/响应及输入产生输出的机制单元。
- [ ] 台账至少记录 chapter/section、mechanism、required_terms、trigger_or_goal、observable_story_or_example、analogy_required、analogy_or_direct_demonstration、analogy_mapping、technical_mapping、input_decision_action_output_handoff、analogy_boundary、status 和 reason。
- [ ] 每个机制都形成“目标或触发 → 当前信息 → 判断或动作 → 结果 → 下一交接”的连续链路。
- [ ] 删除专业术语后，新手仍能复述谁要完成什么、看到了什么、做了什么、结果怎样以及下一步交给谁。
- [ ] 图表引导句、定义、组件清单或通用输入输出句没有被单独当作机制解释。
- [ ] 优先复用贯穿场景；抽象、关系型、不可直接观察或容易混淆的机制必须补充准确短类比；可直接观察的机制可用具体数值、实物、报文或动作演示代替，但已记录省略类比的理由。
- [ ] 所有 rewrite/layer 项均已落实，最终台账状态全部为 pass。
- [ ] 机制练习要求学习者重建动作链，而不只识别术语。
- [ ] 没有机械重复“Imagine”“Think of”“就像”或统一五段模板。

## 2D. 系统化深度与索引化风险

- [ ] 每个主干模块均说明价值、体系定位、概念关系、基本机制和实际场景，而不是只列定义。
- [ ] 学习目标中的“理解、解释、判断、应用或排障”在正文中有对应学习支架。
- [ ] 上游模块的输出、当前模块的判断以及下游接收者能够连成链路。
- [ ] 实践型章节给出观察对象、检查方式、证据含义和证据限制。
- [ ] 英文独立版继承主版本的技术密度、操作价值、安全扩展、练习推理和故事闭环，没有压缩成技术索引。
- [ ] 扩展内容没有挤占主干，但主干所需关系和大概原理也没有因“新手友好”而被删掉。

## 3. 课程主线与章节价值入口

- [ ] 详细目录和正文前有 4–7 行学习主线速览，按阶段、当前问题、核心对象或动作和新人记忆点呈现；它不提前教学未定义术语，也不冒充正式模型。
- [ ] 每个主干模块有明确核心问题，入口自然呈现人物需求、阻碍、技术必要性和采用后结果，没有使用“模块定位”等作者视角元话术。
- [ ] 每个主干模块机制完成后有短、正向、准确的记忆锚点，且锚点未替代定义、机制、关系或边界。
- [ ] 每个技术章节在定义前说明人物需求。
- [ ] 明确指出当前阻碍或缺失能力。
- [ ] 解释为什么需要本章技术，而不是只描述它是什么。
- [ ] 说明采用后能够实现的结果。
- [ ] 后续案例用于演示机制，没有重复入口故事。

## 4. 主链路与故事

- [ ] 全课程有清楚的起点、目标和最终结果。
- [ ] 每一步包含起点信息、判断、动作、结果和下一组件。
- [ ] 上一模块的输出能够自然成为下一模块的输入。
- [ ] 同一组概念尽量复用统一场景和人物。
- [ ] 故事结束后已映射回技术机制并指出类比边界。

## 5. 全书一致性

对每个核心结论回查以下位置：

| 位置 | 检查内容 |
|---|---|
| 总览 | 是否看得到代表性重点和正确定位 |
| 学习目标 | 是否与章节实际深度一致 |
| 正文 | 定义、机制和边界是否准确 |
| 案例 | 是否按正文规则运行 |
| 对比表 | 是否为了简短而重新绝对化 |
| 常见误区 | 是否与修订后的结论一致 |
| 练习与答案 | 是否使用相同前提和技术边界 |
| 最终总结 | 是否保留关键条件且可复述 |

## 5A. 边界与误区的必要性

- [ ] 边界只在省略后会形成错误模型、错误诊断或无条件承诺时出现。
- [ ] 没有机械地为每章重复固定“常见误区与边界”标题。
- [ ] 条件优先放在相关机制、关系、证据或案例旁，并使用符合章节目的的标题。
- [ ] 独立误区章节只保留高频且真实的误解，没有为凑数量制造牵强内容。
- [ ] 边界表述足以纠错，但没有扩展成打断新手主线的穷举规范。

## 6. 排障与证据

- [ ] 每项测试完整记录证据四元组：观察、支持的判断、不能证明的范围、下一项区分性测试。
- [ ] 没有把局部成功当成整条链路完全正常的证明。
- [ ] 下一项测试能够区分剩余假设，而不是机械重复同类检查。
- [ ] 排查顺序根据现象和证据选择，不机械规定唯一入口。
- [ ] 存在方向性的流程已分别重建正向与反向路径，并检查路由、策略、状态和依赖造成的非对称故障。

## 7. 双语内容一致性

- [ ] 中文版和英文版采用相同的课程结构、学习目标和知识覆盖范围。
- [ ] 正式标准、教学模型、产品实现及其适用边界在两个版本中含义一致。
- [ ] 案例可按语言习惯自然表达，但人物目标、问题、技术作用和结果没有改变。
- [ ] 对比表、误区、练习题、参考答案和最终总结在两个版本中相互对应。
- [ ] 英文版不是机械逐句翻译，表达自然且没有遗漏中文主版本中的限定条件。
- [ ] 两版在技术深度、操作证据、安全扩展、练习答案和故事闭环上等值，而不只是目录和标题对应。

## 7A. 能力进阶与跨课程迁移

- [ ] 高频混淆概念集中为最必要的 6–10 组核心关系速查，每组只保留职责、位置、核心差异和不可替代关系的新人级结论。
- [ ] 表格、图和卡片数量受控且各有独立学习任务；Word 连续正文未被单单元格提示卡或重复“模块定位 / 重要辨析 / 核心结论”卡片切碎。
- [ ] 课堂演示建议为 3–6 项，每项都有可观察动作或状态变化并映射回正式机制，没有引入新知识范围或挤入学员主线。
- [ ] 跨课程迁移只复用了教学能力；范围回归检查确认课程地图、速查和演示等新增结构未带入来源范围外的新核心概念。
- [ ] 课程评估覆盖 Recognize、Explain、Reconstruct、Troubleshoot 四级能力，而不是只检查术语记忆。
- [ ] 学习者需要脱离原文复述或画出主链路，才能通过 Reconstruct 层级。
- [ ] Troubleshoot 层级要求依据有限证据区分假设并选择下一项测试。
- [ ] 高频混淆或协作概念有集中式多维对比，覆盖职责、输入输出、位置、依赖、证据和不可替代关系。
- [ ] 比较不同课程时提炼的是可迁移教学能力，没有按篇幅、知识点数量或主题术语简单判优。

## 7B. 存储、RAID 与分布式保护专项

- [ ] RAID 案例已先定义活动成员盘、额外热备盘和编号，明确哪些设备参与原始容量、可用容量和保护计算。
- [ ] 容量与故障示例画清物理成员→镜像对/保护组→组合阵列→逻辑卷；raw capacity、单组容量、多个独立卷总和与组合阵列容量没有混用。
- [ ] 六成员 RAID 1、三组独立双盘 RAID 1 和 RAID 10 的组织差异先由布局说明，再做容量或故障比较。
- [ ] stripe、chunk、parity、degraded I/O、rebuild 与 verification 依赖顺序正确，并有可预测动作的直观支架。
- [ ] Ceph replicated pool 完整覆盖完整副本、`size`、`min_size`、primary/peer acknowledgment、failure domain、recovery/backfill 和容量/性能代价。
- [ ] Ceph erasure-coded pool 完整覆盖 `k` data shards、`m` coding shards、编码/确认、故障后的 reconstruction、failure domain 和小写入/网络/计算/恢复代价。
- [ ] 两类 pool 都连接到 object→pool→PG→CRUSH→acting set→OSD 主链，并通过对比、练习和答案形成覆盖闭环。
- [ ] 已明确 RAID、副本和 EC 都不能单独提供独立历史恢复，也不自动替代备份。

## 8. 限定来源充分性

- [ ] 用户手册覆盖对象、功能、配置条件和操作入口。
- [ ] 技术白皮书覆盖定位、架构、机制、设计原则和能力边界。
- [ ] 运维手册覆盖部署、维护、升级、监控、故障和操作风险。
- [ ] FAQ 覆盖常见问题、限制和易错点，但未被当作完整规范。
- [ ] 已检查发行说明、HCL/兼容性、产品与授权矩阵、迁移支持矩阵、API、规模/性能限制和行业标准缺口。
- [ ] 报告分别说明“事实来源充分性”和“教学设计充分性”，没有把二者混为一谈。

## 9. 语义层与解释模式审计

- [ ] 每个核心概念或机制已选择 `concept_first_analogy`、`analogy_first` 或 `direct_demonstration`，没有把类比先行当作机械固定顺序。
- [ ] 需要精确成员身份、方向或映射关系的主题优先采用概念先行；可直接观察的容量、布局、报文和操作优先采用直接演示。
- [ ] 生活故事内部只包含生活人物、生活目标、生活阻碍、判断、动作、交接和结果。
- [ ] 技术主体、技术单位、正式组件和产品机制没有进入生活故事。
- [ ] 生活事件结束后才开始术语映射；技术重放没有残留隐喻名词。
- [ ] 业务案例与生活类比分开审计，没有因业务案例具有人物和事件就把它计为类比。
- [ ] `pool/unit/member/page/chunk/stripe/object/shard/path/queue/target/lease/room/warehouse/parcel` 等碰撞词已逐处人工确认语义层。
- [ ] 机制台账包含 `explanation_mode`、`semantic_layer_separation` 和 `hybrid_language_scan`，所有主干项均为 pass。
- [ ] LVM 等精确机制先定义 PV、extent、VG、LV 与映射，再用纯生活故事辅助理解；故事中没有 database、TB 或 LVM 术语。
- [ ] Ceph、RAID、EC 等内容中的生活故事、正式机制与真实业务案例边界清楚。
- [ ] 中英文版本采用相同解释模式、映射关系和边界，没有一版纯技术、一版混合类比。
- [ ] 全书语义层混写缺陷数量为 0；发现问题时已同步回查正文、图表、练习、答案和术语表。
